# Итоговый отчёт по проекту LocLLM
**Автор:** Эсен Амирхан | **Проект №2444** | **Дата:** 22.10.2026

## 1. Архитектура решения

Система состоит из 4 модулей, связанных через JSON/CSV:

1. **Dataset Builder** (`build_dataset.py`) — генерирует 150 синтетических учебных изображений (графики, код, формулы, слайды, схемы) с эталонными ответами в `metadata.json`.
2. **Benchmark Runner** (`run_benchmark.py`) — пакетный опрос 3 локальных моделей через Ollama API, замер latency и RAM, сохранение сырых ответов в `raw_results.jsonl`.
3. **LLM-as-a-Judge** (`evaluate_judge.py`) — автоматическая оценка ответов через Gemini API (gemini-3.5-flash-lite), шкала 1-5 по точности и галлюцинациям, агрегация в `results.csv`.
4. **Web Interface** (`app.py`) — Streamlit-приложение для интерактивной демонстрации: загрузка картинки → выбор задачи → ответ модели с метриками.

## 3. Анализ характерных ошибок

### Паттерн 1: Обрыв генерации (early stopping)
**Модель:** Moondream2, Mistral NeMo Vision | **Категории:** графики, схемы
Ответ обрывается на середине предложения; сигнатура `acc=1-2, hal=4-5`. Модель не выдумывает, но не раскрывает вопрос. Связано с лимитом `max_tokens` в профиле и слабой когезией малых VLM.

### Паттерн 2: Repetition loops (зацикливание)
**Модель:** Moondream2 (реальный прогон) | **Все категории**
Модель зацикливается на одном токене (`"количество количество количество..."`) или повторяет фрагменты промпта. Критическая деградация edge-моделей на CPU без flash-attention.

### Паттерн 3: Prompt echo (эхо промпта)
**Модель:** Moondream2 (реальный прогон)
Модель возвращает части системного промпта как ответ. Сигнал слабого понимания инструкций у 1-2B моделей.

### Паттерн 4: OCR-отказ с оправданием
**Модель:** Moondream2 | **Категории:** формулы, код
Вместо LaTeX/кода модель даёт уклончивый ответ с выдуманной причиной: «часть мелких символов распознана с искажением», «плохое качество изображения». Комбинация умолчания и галлюцинации-оправдания.

### Паттерн 5: Правдоподобное числовое искажение
**Модель:** Mistral NeMo Vision | **Категории:** графики, схемы
Ответ структурно повторяет эталон, но содержит выдуманную вставку («возможна погрешность в крайнем значении по оси»). Самый опасный паттерн: текст выглядит экспертным, но содержит ложные уточнения.

## 4. Выводы о применимости

1. **Модели 11-12B (Llama-3-Vision, Mistral NeMo Vision)** — пригодны как учебный ассистент для структурированного контента (код, слайды, схемы). Accuracy 4.7-5.0 при latency 4-5 сек. Требуют ≥16 ГБ RAM или GPU.
2. **Edge-модель Moondream2 (1.8B)** — на CPU MacBook Air демонстрирует severe degradation: accuracy падает до 1.0, latency растёт в 7.5 раз, 60% ответов зацикливаются. Непригодна для production-сценариев без GPU и специализированного runtime (llama.cpp + Q4 + flash-attention).
3. **Профильный режим (Safe Mode)** даёт оптимистичную верхнюю границу качества и применим только для архитектурной валидации, не для production-оценки.
4. **LLM-as-a-Judge (Gemini)** показал высокую согласованность с заложенными дефектами: различает «ошибки умолчания» и «ошибки вымысла», что валидирует саму методологию оценки.

## 5. Ограничения и дальнейшие шаги

- Текущий датасет синтетический; для production требуется валидация на реальных учебных материалах (ChartQA, DocVQA).
- Требуется интеграция с llama.cpp для квантованных моделей и flash-attention.
- Необходим A/B-тест с экспертной оценкой для калибровки метрик судьи.
